# 반응형 QA 기준

최신 Figma Make의 QR 구매 화면을 기준으로 아래 뷰포트를 확인합니다. 브라우저와 앱 WebView의 글꼴 렌더링 차이 때문에 픽셀 하나까지 동일하다고 보장하지는 않지만, 정보 구조·색상·간격·고정 주문 영역·상호작용은 동일하게 유지합니다.

| 환경 | 기준 크기 | 확인 항목 |
| --- | ---: | --- |
| 소형 모바일 | 360×800 | 320px 이상 가로 스크롤 없음, 가격·주문 CTA 겹침 없음 |
| 일반 모바일 | 390×844 | Figma 모바일 시안, 안전 영역, 하단 고정 CTA, 모달 |
| 태블릿 | 768×1024 | 주문 폼과 결제 요약 2열, 입력 영역 최소 폭 |
| 데스크톱 | 1440×900 | 작품 상세 2열, 최대 폭 1120px, 고정 구매 영역 |

## 흐름 검증

1. 서로 다른 QR 토큰이 서로 다른 작품·가격·재고를 조회한다.
2. 작품 상세를 먼저 보고 주문할 때만 연락처 확인 화면이 열린다.
3. 연락처 확인 후 동일 QR와 수량이 결제 화면까지 유지된다.
4. 카드·간편결제 선택, 카드사·할부 선택 목록이 화면 밖에 갇히지 않는다.
5. 서버가 가격과 재고를 다시 계산하고 품절·초과 수량을 거부한다.
6. 주문 완료 후 같은 주문 ID로 주문 내역을 다시 열 수 있다.

## 디자인과 운영 구조가 다른 지점

Figma 데모의 작품 전환 버튼은 로컬 고정 목록을 탐색합니다. 실제 QR 화면은 한 토큰이 한 매장·한 작품을 가리키므로, 서버가 관련 작품과 각 QR 토큰을 제공하기 전까지 해당 버튼을 숨깁니다. 보이는 모양만 맞추기 위해 동작하지 않는 버튼을 노출하지 않습니다.
