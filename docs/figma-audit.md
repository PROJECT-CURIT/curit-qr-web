# Figma Make 코드 점검

## 가져온 범위

- 작품 상세: 대표 이미지, 작가 정보, 가격·재고, 작품 이야기, 상품 정보, 수령·교환
- 주문: 수량, 주문자 정보, 카드·간편결제 선택, 개인정보 동의
- 주문 완료·주문 내역
- 즉시 현장 수령과 전시 종료 후 수령
- 모바일 중심 반응형 UI와 PWA 기본 자산

## 그대로 사용할 수 없었던 부분

1. 기존 QR은 URL 해시에 상품 JSON 전체를 넣어 가격·재고를 브라우저가 신뢰했습니다. 사용자가 값을 바꿀 수 있어 운영에 사용할 수 없습니다.
2. 주문과 인증이 `localStorage`에만 저장돼 다른 기기·매장·앱과 공유되지 않았습니다.
3. 결제 버튼이 실제 PG 승인 없이 성공 주문을 만들었습니다.
4. 매장 앱으로 주문 JSON을 URL 해시에 돌려보내는 구조는 위조와 URL 길이 문제를 만들었습니다.
5. 상품을 보기 전 휴대폰 번호를 요구해 QR 유입의 탐색 전환을 떨어뜨릴 가능성이 있습니다. 현재 화면 일치는 유지했지만, PoC에서는 `상품 탐색 → 주문 시 연락처 입력` 순서와 A/B 비교가 필요합니다.

## 변경한 경계

- QR은 서버가 발급한 토큰만 포함합니다.
- 상품·가격·재고는 API 응답만 사용합니다.
- 주문 금액은 서버가 다시 계산합니다.
- 주문 시 재고는 서버에서 원자적으로 차감합니다.
- 데모 결제는 주문 완료 화면에서 실제 결제가 아님을 명시합니다.
- 운영 DB와 앱은 `curit-api`를 공통으로 사용합니다.
